# ComputerUse-DSH 2.3.0-rc.1 验证报告

基线为 V2.2.1。测试覆盖 Node 插件、Python MCP、隔离 DSH 0.2.2-rc.3 Profile、合成数据和单屏 Windows 实机。Token 结果来自本地回放。

## 第一阶段　会话和输入安全

- DSH 通过受信任的会话对象建立短期观察范围。不同会话可分别持有最近成功交付的截图。截图交付失败、撤销授权、服务退出或桌面输入后，旧引用无法继续驱动输入。
- 坐标使用前复核监视器布局、前台窗口和鼠标命中位置。键盘输入在提交前复核原焦点；长文本和连续按键在后续输入点继续检查焦点。后台图片只用于观察。
- 审批通过后并行准备 Python 服务和原生提示层，提示层应报告已排除窗口捕获。测试涵盖禁用、排除确认失败、延迟退出与空闲回收。分段计时只保留最近 64 项标量样本，无桌面内容写入。
- 两个发布产物已分别装入临时 Python 环境和隔离 DSH Profile。Python 包包含 x64 原生辅助程序。生产 DSH 应用、活动 Profile 和正式回退备份由现行安装继续使用。

## 第二阶段　窗口捕获与 UIA

- UIA 查询和控件等待通过有时限、有限额的只读进程执行。隔离测试使用故意阻塞的子进程，验证只终止当前读进程、其他读操作仍可运行、后续请求可以恢复。
- UIA 按窗口句柄与 PID 读取范围，在遍历直接子元素时批量读取 COM 缓存属性。控件操作仍通过实时窗口及控件检查。缓存接口不适用时可使用现有有界读取。
- 后台窗口截图在子进程内裁切，使用 PrintWindow，并在失败或整窗图无有效内容时尝试窗口级 Windows Graphics Capture。两套后端都检查窗口身份、位置、显示状态和截图保护。WGC 保留系统指示边框。测试验证负坐标裁切、失败回退、权限拒绝和取消。原生程序已用 MSVC 和 Windows SDK 编译通过。

## 第三阶段　历史精简与成本

- 精简使用 DSH 原生图片卸载与消息替换事件。要求观察目标、参数和内容指纹相同。失败、未确认的输入、内容不同的同尺寸截图、旧版无指纹观察会保留。原始日志和附件可回看。

## 单屏实机验收

- 在独立 WinForms 测试窗执行前台截图、使用截图坐标点击、按键和中文粘贴。由测试窗读回按钮计数和文本。不同 DSH 会话共享后台服务时，跨会话截图 ID 和输入后失效的旧帧均被拒绝。
- 在实际 UIA 提供程序中查询控件、切换复选框并读回状态。Windows 英文 OCR 在候选版截图中定位到唯一的测试文本。
- 用第二个测试窗口遮住目标窗，PrintWindow 正确返回指定裁剪。测试注入一次 PrintWindow 空结果，真实 Windows Graphics Capture 后备程序返回有效的 450 × 260 图像。后台帧拒绝用于坐标点击。
- 实际启动原生提示进程。黑箭头位置更新收到渲染回执，同一固定测试区域的截图像素在显示提示时保持一致，操作结束后提示隐藏。
- 用独立 Electron 数据目录启动 DSH。候选插件注册 14 项标准工具，宿主报告工具、附件及审批服务可用。候选插件操作链路通过隔离桥接夹具验证。多屏和远端模型请求未纳入本轮。
- 使用 DSH 原生 headless 运行器和本地测试模型，实际调用 `wdc_wait`、`wdc_screen_info` 和 `wdc_window_screenshot`。候选 Node 与 Python 版本一致，工具目录匹配。DSH 将 340 × 170 的专用窗口 PNG 保存为原生附件，并把附件引用传入下一次本地模型请求。
